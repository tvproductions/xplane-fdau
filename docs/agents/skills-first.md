# Mandatory starter alignment

FDAU adopts the released skills-first starter's heavy lane. The selected starter
version, full revision and independent component pins live in
`.skills-first/bundle.lock.json`; `.codex/config.toml` selects that one shared
marketplace. `AGENTS.skills-first.md` is its generated routing and policy fragment.
Project domain authorities and the approved scope amendment remain binding.

Heavy is an explicit selection in `.gz-skills/settings.json`. Backplane remains
disabled because readiness is pending. No requirements or delivery state moves
out of BACKLOG/ROADMAP, and this adoption introduces no gzkit lifecycle.
Configuration, installation, actual discovery, Python engineering acceptance and
whole-stack readiness are distinct observations. The
[dated adoption record](../reviews/2026-10-25-strict-heavy-starter-adoption.md)
keeps their evidence and gaps. Required failed, unknown or stale evidence blocks
STRICT acceptance. A profile choice or a passing routine suite cannot close it.

Use the native manager to inspect marketplace/plugin identities and actual source
revisions. A fresh project session must discover the selected Superpowers and
gz-skills entry skills and the project-owned `update-gz-template` skill. Keep old
sources disabled only in FDAU; preserve unrelated installations and user defaults.
The main checkout's old junction is rollback state until integration reconciles
it. Never recursively remove a junction target or edit a managed plugin cache.

Invoke `update-gz-template` for template review or an authorized migration. Its
mode follows the request: checking for updates does not authorize applying them.
Use canonical `gzs-update-dependencies` for tool maintenance and its project
adapter for the Python/uv surface. Independently inventory starter, Superpowers,
Backplane and gz-skills at adoption, scoped maintenance, quarterly on demand and
release acceptance. Compare released policy as well as versions; record dated
adopt/defer decisions and preserve application additions. No scheduled updater
is installed. A newer upstream component does not justify a private FDAU catalog.

Product versions follow SemVer independently of template and plugin versions.
Every major release, including 1.0.0, requires a newly written and reviewed PRD in
FDAU planning authority, linked from the existing release/backlog record. Minor
releases collect coherent selected work and compatibility notes; patches preserve
compatibility. G1 remains waiting for the canonical vertical slice. Git sync,
integration, tagging and publication retain their separate authorization gates.

The [Python engineering policy](../engineering/python.md) supplies executable
commands and measurement obligations. Historical plugin-only adoption evidence
remains historical; its original source selection no longer governs this branch.
