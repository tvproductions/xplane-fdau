## Global Constraints

- Implement only C2.3. C2.2 is verified and integrated. Preserve existing canonical and native FDR behavior. No runtime dependency, host/network import, acquisition, algorithm execution or provider content.
- “Every public structural model class above is a frozen, slotted, keyword-only dataclass.” Closed vocabularies are `enum.StrEnum`; no additional public structural class, constructor field, semantic default or compatibility alias.
- “Sequence inputs are defensively copied to tuples before validation.” Accept ordered lists/tuples; reject sets and arbitrary iterables. Recursively freeze caller-owned parameter/selection mappings; never silently sort or deduplicate semantic arrays.
- “JSON `null` is prohibited throughout version 1.” Optional properties are omitted; distinguish explicit `None` from omission with the existing private sentinel. Reject Boolean-as-integer and preserve lexical integer/real domains.
- “No model can hold a caller-supplied stale self-hash.” Use a cached non-init private slot and read-only `content_hash`; definition hashing uses the source-binding catalog family URI, schema version integer `1`, and the complete entry excluding only its own hash, including final LF.
- IDs use `[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+`, at most 255 ASCII characters; revisions are 1 through `2^63-1`. Resource IDs are NFC text up to 2048 code points, not semantic identifiers. Parameters are data-only objects, depth at most 32; document nesting is at most 64.
- Provenance, applicability, dependencies, companions, transforms and limitations have at most 256 entries. Other arrays/objects, including each nonempty transform-input array, have at most 65535. Follow specification semantic property order within each validation tier; wire keys use canonical lexical order.
- Binding references pin exact ID/revision/hash syntactically here. Resolving measurement existence/hash, final/direct compatibility, applicability narrowing and measurement-authorized failure outcomes belongs to C2.4. Sample disposition evaluation belongs to C3; algorithm registry/execution belongs to A1.4.
- Keep contracts inward and unchanged. Public `definition_ref`, `record_ref`, `compute_content_hash` and structural-model dispatch in public `canonical_bytes` remain the existing C4.3 closure obligation. No new shared dispatcher, upward imports or early public binding loader/schema.
- Python support remains `>=3.12,<3.13`, selected patch `.python-version` (3.12.16 at planning), runtime requirements `[]`, unittest only, hooks enabled. Use the project-required uv 0.13.6 in the process PATH, including child processes/hooks; do not alter global tools or pins to run this plan.

## Review Focus

1. A resource-selection dict or nested algorithm parameter list can mutate identity after construction: Task 1 mutation controls and Task 2 hash stability tests must prove deep ownership.
2. An alias differing only in provider/adapter version can evade source uniqueness: Task 2 pins the specified resource key and checks primary/dependency/companion collisions, preserving declaration order.
3. A transform may accidentally consume a companion, a future step or an output with incompatible payload/shape: Task 2 tests each disallowed edge and every input declaration dimension without executing algorithms.
4. An early invalid semantic field or stale hash may hide a later wrong-type/null field: Task 3 competing-error tests and constructor barriers prove complete-entry tier ordering and exact RFC 6901 paths.
5. A failure policy can promise unusable flagged evidence: Task 1 rejects `accept_flagged` for unavailable/orphaned/read_error; Task 4 makes the deferred measurement-authorization boundary explicit and proves installed public construction.
