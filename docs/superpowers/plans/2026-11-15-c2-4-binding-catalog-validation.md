## Global Constraints

- Implement only C2.4 after approval and execution-method selection. Python support remains `>=3.12,<3.13`, development pin `3.12.16`; runtime `dependencies = []`. Use unittest only. Preserve root exports, native FDR behavior and the inward bindings -> measurements/contracts dependency direction.
- “Every public structural model class above is a frozen, slotted, keyword-only dataclass.” “Sequence inputs are defensively copied to tuples before validation.” Reject unordered/arbitrary iterable inputs; never silently sort or deduplicate.
- “Optional properties are omitted when absent.” “JSON `null` is prohibited throughout version 1.” Preserve integer/real token distinctions, reject Boolean numeric coercion, and retain identical constructor/loader property paths.
- Source-binding family URI is exactly `https://tvproductions.github.io/xplane-fdau/contracts/source-binding-catalog`, schema version integer `1`; schema `$id` is exactly `https://tvproductions.github.io/xplane-fdau/schemas/source-binding-catalog-v1.schema.json`.
- The catalog uses the measurement catalog's exact top-level inventory: `contract_family`, `schema_version`, `catalog_id`, `catalog_revision`, `authority`, nonempty `provenance`, optional `title`, optional `scope`, nonempty `definitions`, `content_hash`, in semantic validation order. Constructor required fields precede optional fields. Definitions are unique and ordered by `(definition_id, definition_revision)`; multiple revisions of one ID are valid.
- “A top-level record's preimage is the canonical JSON encoding of that object with only its root `content_hash` property omitted, including the final LF.” “Nested objects keep their hashes when an enclosing hash is computed.” Binding-entry hashes retain the source-binding-family/version envelope. Self-hashes are computed cached properties, never constructor arguments.
- Catalog definitions contain at most 65535 entries; provenance and binding applicability/dependencies/companions/transforms/limitations at most 256. Whole-document nesting is at most 64, counting the catalog root; algorithm parameter nesting is at most 32, counting its object root. Do not reset document depth at each entry.
- Preserve the six loader tiers: parse/duplicates -> family/version -> complete shape -> complete canonical domains -> all well-formed self-hash comparisons -> local semantics -> construction. Within a tier, use semantic field order and increasing array index. Malformed hash spelling belongs to semantics, not mismatch comparison.
- “It neither registers catalogs globally nor executes algorithms.” Catalog construction/loading establishes local validity without requiring a measurement catalog; `validate_binding_catalog` performs the explicit separate cross-document operation. No provider I/O, registry/import resolution, algorithm implementation, sample evaluation, value normalization or acquisition behavior.
- No product catalogs, DataRefs, aircraft/plugin bindings, runtime fixtures or new conformance-corpus claim. Use synthetic `test.*` test/example identities. C4.2 owns corpus closure; C4.3 owns existing deferred shared `definition_ref`/`compute_content_hash`/public `canonical_bytes` model dispatch. Keep those shared contracts APIs unchanged in this child.
- Schemas use Draft 2020-12, the exact eight root keys, local `$defs` references only, no defaults, closed structural variants, canonical UTF-8 without BOM and one LF. Equal named shared `$defs` match the delivered measurement schema byte-for-byte as canonical subtrees. JSON Schema does not establish lexical number domains, NFC, hashes, ordering, cross-field policies or reference closure.
- New modules and a shipped schema require one stable full offline hygiene pass, which supplies the complete routine gate; do not add a second aggregate on the unchanged candidate. Keep mandatory hooks enabled. G1, incomplete STRICT evidence, remote sync, integration and publication retain their existing separate gates.

## Review Focus

1. A malformed later definition must outrank an earlier semantic/hash failure, with zero premature constructors: Task 2's competing-tier tests and actual-initializer barrier.
2. A valid binding-entry parameter at depth 32 must still obey whole-catalog depth 64, and parameter-domain errors must occur at their semantic position: Task 2's embedded-depth and competing-domain controls.
3. Same ID/different revision, multiple corroborating bindings and shared resources across distinct bindings are valid; reference hashes and exact payload/shape declarations remain strict: Tasks 1 and 3.
4. Quality authorization alone cannot authorize a disposition whose validity row or absent-normalization outcome is impossible: Task 3's full six-condition/four-disposition table.
5. Short-writing/nonseekable caller-owned streams and installed schema access must work outside the source checkout: Task 2 stream controls and Task 5 external proof.
