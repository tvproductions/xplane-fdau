## Global constraints

- Use Python `>=3.12,<3.13` with the current project pin `3.12.16`, uv `0.13.6` and unittest. Runtime dependencies remain empty. Preserve the version-only root namespace and inward `acquisition` dependencies on contracts, measurements and bindings.
- The literal family is `https://tvproductions.github.io/xplane-fdau/contracts/raw-observation`, version integer `1`. The schema ID is `https://tvproductions.github.io/xplane-fdau/schemas/raw-observation-v1.schema.json`. Instances have no `$schema` member. Emit canonical UTF-8 without BOM and with one final LF. Optional properties are omitted. Version 1 prohibits JSON `null`.
- Public records are frozen, slotted, keyword-only dataclasses. Copy ordered sequences to tuples and resource selection to a read-only copy. Reject unordered containers, unknown/irrelevant properties, Boolean numeric coercion and integer-to-real coercion. Preserve ordering and exact evidence. Applicability is unique and sorted by `class_id`. Limitations preserve input order and are unique. Each collection has at most 256 items.
- Preserve complete load precedence: parse and duplicates, family/version, shape, canonical domains, self-hash, local semantics. Apply semantic property order within each phase. Use RFC 6901 paths and preserve source, family, recoverable record identity and parser locations. Never quote raw inline values or payload contents in diagnostic messages.
- Calculate the root hash with only root `content_hash` omitted. The preimage includes the final LF and all nested fields, including the payload reference's `sha256`. Use the existing `_record_content_hash` and `_encode_document`. Cache the result in a private non-init slot exposed by a read-only property.
- C3.2/C3.3 own samples, lineage and catalog-resolved quality and declaration checks. C3.4/C3.5 own frames. C4.1–C4.4 own family-wide resource inventory, conformance corpus and shared API/artifact closure. Preserve the existing C4.3 deferral for shared `canonical_bytes` dispatch, `compute_content_hash` and `record_ref`. This plan adds the four raw-observation family I/O functions. Payload resolution, acquisition, recording, transform execution, provider code and native FDR changes are outside scope.

## Review focus

1. A validly rehashed record can still contain unacceptable evidence. Task 3 tests the status matrix and competing validation phases, including malformed later shapes and zero premature construction.
2. Receipt timing is mandatory and source timing survives only when genuinely supplied. Tasks 2 and 3 test receipt-only, distinct optional clocks, matching anchors and conflicting clock or producer identities.
3. An empty array, scalar `False` and absent evidence carry different information. Task 2 tests each, plus wrong inline element representation and independently retained payload metadata.
4. Array-set order, claimed raw shape and mutable caller inputs can change identity if mishandled. Tasks 2 and 3 pin ordering, defensive copies, semantic error paths and independently hashed bytes.
5. Draft 2020-12 validates structural shape but cannot establish hash or lexical number semantics. Tasks 1, 3 and 4 test those distinctions, resource parity and the public API from an installed wheel.
